# Инструкция: прогнозы 1X по дампам БД

## Задача
Пользователь присылает файл(ы) `matches_with_stats.sql` (SQL-дамп, INSERT-запросы).
По каждому матчу в дампе нужно выдать **только одно из двух**:
- `1X` — если есть железобетонная уверенность, что хозяева не проиграют (победа или ничья)
- `воздержался` — если есть хоть малейшее сомнение

Формат ответа — список "Команда1 — Команда2: вердикт", без лишних комментариев,
если пользователь не просит пояснить. Прогноз всегда только на 1X, других рынков не давать.

## Формат дампа
Таблица обычно называется `upcoming_matches_team_stats`. Колонки (28 шт., в этом порядке):

1. `fixture_id` — id матча, на который прогнозируем
2. `kickoff` — дата/время матча
3. `competition` — турнир предстоящего матча
4. `team1` — **хозяева** предстоящего матча
5. `team2` — **гости** предстоящего матча
6. `side_flag` — `team1_home` / `team2_away` (какая из строк какой команде принадлежит)
7. `team` — имя команды, к которой относится историческая строка (team1 или team2)
8. `hist_id` — id исторического матча
9. `hist_date` — дата исторического матча (может быть NULL)
10. `hist_status` — обычно `finished`
11. `hist_competition` — турнир исторического матча
12. `hist_side` — `home`/`away` — на каком поле играла команда в этом историческом матче
13. `hist_opponent` — соперник в историческом матче
14. `goals_for`, `goals_against` — счёт (голы команды / голы соперника)
15–28. xg, possession, shots_total, shots_on_target, big_chances, corners, fouls,
   offsides, yellow_cards, red_cards, passes_completed, passes_total, pass_accuracy
   (много NULL, не критичны для прогноза)

Иногда встречается более простая таблица `matches_with_stats` (без team1/team2/fixture_id) —
это просто список законченных матчей с полной статистикой, используется как общая база
для расчёта формы, если нет `upcoming_matches_team_stats`.

## Как обрабатывать дамп (пошагово)

1. **Собрать в SQLite** (Python, sqlite3 встроен, CLI `sqlite3` может отсутствовать):
   ```python
   import sqlite3
   conn = sqlite3.connect(':memory:')  # или файл
   c = conn.cursor()
   c.execute("CREATE TABLE upcoming_matches_team_stats (fixture_id TEXT, kickoff TEXT, ...)")
   c.executescript(open(path).read())
   ```
   Важно: заранее сосчитать реальное число колонок в сыром INSERT (парсить построчно,
   учитывая кавычки), а не полагаться на память — формат менялся между дампами.

2. **Проверить на "утечки" результата.** Иногда `upcoming`-матч уже сыгран к моменту
   выгрузки, и его результат затесался в историю самой команды:
   ```sql
   SELECT * FROM upcoming_matches_team_stats WHERE hist_id = fixture_id
   ```
   Если такие строки есть — матч уже завершён, счёт известен из `goals_for/goals_against`.
   На такие матчи прогноз не даём («матч уже сыгран»), это не 1X и не «воздержался».

3. **Исключить категории с непредсказуемым составом / контекстом** — по ним всегда
   `воздержался`, не тратя время на анализ статистики:
   - Товарищеские/отборочные матчи сборных, Nations League, U-любых-лет (Elite League U20 и т.п.)
   - Кубковые турниры низших раундов, где топ-клубы выставляют дублирующий/молодёжный состав
     (EFL Trophy, National League Cup в Англии, Copa Argentina иногда, Кубок Бельгии ранние раунды)
   - Разовые/товарищеские кубковые финалы (International Super Cup и т.п.)
   Признак риска: у "гостевой" команды из такого турнира `overall n=0` (нет истории вообще) —
   это значит выступает не основной состав.

4. **Для оставшихся (реальных лиговых) матчей** — для каждой команды достать историю,
   отсортированную по дате, исключив саму строку с `hist_id = fixture_id`:
   ```sql
   SELECT hist_date, hist_competition, hist_side, hist_opponent, goals_for, goals_against
   FROM upcoming_matches_team_stats
   WHERE fixture_id=? AND team=?
   ORDER BY hist_date
   ```
   Посчитать W/D/L:
   - хозяева: **только домашние матчи** (`hist_side='home'`)
   - гости: **выездные матчи** (`hist_side='away'`) И общий результат по всем матчам
     (`overall`) — обе метрики важны, выездная короче объясняет форму на выезде,
     общая ловит команды, которые просто ни разу не проигрывали (даже если мало
     выездных побед — это не то же самое, что "слабая" команда, см. п.6).

   **КРИТИЧЕСКИЙ БАГ ДАННЫХ (найден при бэктесте, см. "Калибровка" ниже):** в строках
   истории с `hist_side='away'` поля `goals_for`/`goals_against` **не разворачиваются**
   под команду — они дублируют счёт с точки зрения хозяев того исторического матча
   (проверено на 3600+ матчах, видимых с обеих сторон в корпусе дампов: away-строка
   команды всегда содержит ТОЧНО ТЕ ЖЕ значения gf/ga, что и home-строка того же матча,
   без разворота). Итог: при расчёте W/D/L для строки с `hist_side='away'` нужно
   **менять местами** `goals_for` и `goals_against`, иначе выездные победы/поражения
   считаются наоборот. Для `hist_side='home'` строки корректны как есть (это
   единственный надёжный источник истинного счёта матча).
   ```python
   for row in hist_rows:
       gf, ga = row.goals_for, row.goals_against
       if row.hist_side == 'away':
           gf, ga = ga, gf   # fix: away-строки хранят счёт с точки зрения хозяев
       # дальше W/D/L считать по (gf, ga)
   ```
   Бэктест показал, что без фикса методика не портилась качественно (precision 85.4%
   vs 87.4% с фиксом), но пропускала примерно половину валидных кандидатов на 1X
   (41 против 87 на тех же 2741 матчах) — то есть раньше была избыточно консервативна,
   а не ошибалась в другую сторону. С этого момента фикс обязателен.

5. **Проверить прямые личные встречи (H2H)** в этом же сезоне/турнире:
   ```python
   h2h = [r for r in hist_team1 if r.opponent == team2] + [r for r in hist_team2 if r.opponent == team1]
   ```
   Если соперник уже обыграл хозяев в этом сезоне (особенно в том же турнире,
   например обратный матч Кубка) — это красный флаг, дисквалифицирует 1X, даже
   если остальная статистика хорошая.
   **Осторожно:** в дампах встречается баг — обе стороны одного и того же матча
   иногда показывают собственную "победу" с одинаковым счётом (несостыковка данных).
   В таком случае доверять записи той команды, у которой `hist_side` соответствует
   реальному хозяину этого H2H-матча, и относиться к найденному H2H как к поводу
   для осторожности в любом случае.

6. **Критерии для прогноза 1X** (все должны выполняться; пороги откалиброваны бэктестом
   на 2741 реальном матче, см. "Калибровка" ниже):
   - Хозяева: **0 поражений дома** в выборке, и выборка **n≥4** (строгий порог; n=3 даёт
     заметно больше ложных срабатываний при бэктесте, n=2 не использовать вообще)
   - Гости: **явная слабость** — 0 побед на выезде (при n≥3; n=2 слишком шумно) ИЛИ
     0 побед вообще по всем матчам (при n≥4). Просто "мало побед, но и мало поражений" —
     это НЕ слабость (см. кейс Walsall: 0 побед на выезде, но и 0 поражений за 8 матчей
     вообще — крепкая команда, от такого прогноза лучше отказаться)
   - Нет H2H, где гости уже обыграли хозяев в этом сезоне
   - Нет явного противоречия: если у гостей при этом сильный **общий** результат
     (0-1 поражение и 3+ победы в сумме, при n≥4) — не бери в 1X, даже если конкретно
     "на выезде" ноль побед на малой выборке
   - **Еврокубки и континентальные турниры клубов** (Champions League, Europa League,
     Conference League, Libertadores, Sudamericana, AFC Champions League и т.п.) —
     исключать из 1X полностью, независимо от того, прошли ли цифры критерии. На бэктесте
     это самая частая категория ложных попаданий (пример промаха: Manchester City 0:3 PSG —
     цифры формально говорили "гости слабы на выезде", реальность иная). Порог выборки
     (n=2-4) там систематически не отражает истинный класс команд.
   - Кубковые матчи (даже не входящие в п.3) с малой историей (n<3 у любой из команд) —
     дополнительный повод для осторожности

   Если сомневаетесь — `воздержался`. Плотность попаданий важнее количества прогнозов:
   из ~40–100 матчей в дампе обычно набирается 0–3 подходящих под 1X, это нормально.

7. **Ручной override на известный класс команды**: правило из п.6 про еврокубки/
   континентальные турниры уже откалибровано бэктестом и обязательно к применению.
   Дополнительно, даже в домашней лиге/кубке конкретной страны встречаются матчи, где
   "слабый по цифрам" гость — объективно топ-клуб этой страны (например, топ-клуб играет
   кубковый матч против команды низшей лиги, и крошечная выборка истории (n=2-4) случайно
   показывает "0 побед" из-за ротации состава) — в таких случаях даже формально пройденные
   критерии п.6 — повод для `воздержался`, а не 1X. Применять это точечно и редко: для
   обычных лиговых матчей внутри одной лиги (MLS, Serie B, аргентинская Liga Profesional
   и т.п.) малая выборка — это нормальный шум, предусмотренный порогами п.6, и не повод
   для дополнительного ручного вмешательства.

8. **Пересчитывать заново каждый дамп**, не полагаться на предыдущие выводы по тем же
   командам без свежих данных — форма может измениться, а более полный/датированный дамп
   может опровергнуть более ранний вывод, сделанный по неполным данным (так уже было:
   первый разбор Petrolul-Miercurea Ciuc без дат ошибочно посчитал соперника беспомощным,
   хотя тот стабильно побеждал на выезде — после получения дампа с датами прогноз пришлось
   отозвать).

## Формат ответа пользователю

Только список, без обоснований (если явно не просят):
```
- Команда1 — Команда2: 1X
- Команда3 — Команда4: воздержался
...
```

Если в дампе есть матчи, которые пользователь уже "поставил" в прошлый раз (прогноз был дан
в предыдущей сессии) и теперь известен результат — стоит явно сообщить исход (сыграл/не сыграл),
особенно если прогноз не оправдался. Это не "комментарий", а важная фактическая информация,
даже при инструкции отвечать "без комментов".

**Активная проверка исходов прошлых пиков (обязательно на каждом новом дампе):** не ждать
случайной самоутечки — явно прогонять `scripts/check_ledger.py` против всех доступных
SQL-дампов этой сессии (`python3 scripts/check_ledger.py <папка-с-дампами>`). Скрипт ищет
каждую команду-хозяина из `docs/1x-picks-ledger.json` со статусом `unresolved` в колонках
`team`/`hist_opponent` всех дампов (не только текущего — результат может всплыть в истории
СОВЕРШЕННО другого матча, если команда играла с кем-то, кто сам попал в выгрузку) и выводит
счёт из надёжной `hist_side='home'` строки. Любой найденный результат — вручную обновить в
`docs/1x-picks-ledger.json` (`status: "confirmed_hit"` или `"confirmed_miss"`, добавить `score`),
закоммитить. Каждый новый выданный 1X-пик — тоже добавлять в ledger со статусом `unresolved`.
Это даёт настоящий (не выборочный) hit rate методики со временем, а не рассказ по памяти.

## Калибровка (бэктест, 2026-10-24)

Пороги в п.6 выше — не интуитивные, а проверенные бэктестом на историческом корпусе
всех собранных дампов (12 файлов, ~17.5к строк истории). Метод: каждая историческая
строка `hist_id`, видимая в данных **с обеих сторон** (т.е. и как история команды-хозяина,
и как история команды-гостя того же матча где-то ещё в корпусе — таких набралось 3728),
используется как "псевдо-upcoming" матч: берём для обеих команд всю их историю **до**
даты этого матча (после фикса бага из п.4) и прогоняем через критерии п.6, затем
сравниваем предсказание с реальным исходом (из `hist_side='home'` строки — единственного
надёжного источника счёта).

Результат на 2741 валидном кандидате (после исключения сборных/отборочных и матчей без
истории у кого-то из участников):
- **Базовая частота 1X** (хозяева просто не проигрывают, без всякого отбора): 73.9%
- **Критерии п.6 (с фиксом бага, старые пороги n_home≥3/n_away≥2)**: 87 попаданий под
  отбор, precision 87.4% — заметный прирост (+13.5 п.п.) над базовой частотой, отбор
  работает не просто как шум
- **Без фикса бага** (как считалось весь сезон до этой калибровки): только 41 матч
  прошёл отбор при precision 85.4% — то есть баг не портил качество прогнозов, а
  делал методику чрезмерно консервативной (пропускала примерно половину валидных 1X)
- **Калиброванные пороги** (n_home≥4, n_away≥3, искл. еврокубки): 30 попаданий,
  precision 93.3% — лучший баланс точности и объёма среди проверенных вариантов
- Ослабление порога (n_home≥2) роняет precision до 78.9% — почти до уровня базовой
  частоты, подтверждает, что именно требование n≥3-4 отсекает шум
- Самая частая причина промахов на старых порогах — еврокубки/континентальные турниры
  (пример: Manchester City 0:3 PSG формально проходил по цифрам) — отсюда жёсткое
  исключение таких турниров в п.6, а не просто "ручная осторожность"

Скрипты бэктеста и ablation-таблица сохранены в сессии (не в репо, т.к. зависят от
сырых дампов, которых в репозитории нет) — при следующей калибровке стоит повторить
на расширенном корпусе, подход воспроизводим: собрать все дампы в одну таблицу,
найти `hist_id`, видимые с обеих сторон, использовать `hist_side='home'` как истинный
счёт, остальное — по алгоритму п.6.
